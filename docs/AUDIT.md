# Аудит Last Trial of Relics — 30 глобальных проблем

Разбор по двум осям: **как сделано** (код и архитектура) и **как развивается**
(процесс, документация, релизы). Для каждой проблемы: в чём суть, чем грозит,
что сделано и что осталось.

Статусы: ✅ исправлено в 0.4.0 · 🟡 частично · ⏳ план.

---

## A. Ошибки реализации

### 1. ✅ Волны из датапака не загружались вообще

`WaveLibrary` искал файлы через `FileToIdConverter.json("festival/waves")`, то есть
`data/<ns>/festival/waves/*.json`. Наш файл лежит в `data/lasttrial/waves.json`,
у датапаков — тоже в корне. Ни один состав волн не читался, всё собиралось
процедурно, а `/reload` ничего не менял.

**Сделано:** перебор namespace'ов и чтение `waves.json` из корня каждого.
**Осталось:** тест на парсер (нужен ResourceManager).

### 2. ✅ Конфиг обнулял новые поля

`Gson.fromJson(reader, FestivalConfig.class)` создаёт объект в обход конструктора,
поэтому любое поле, которого нет в файле (старый конфиг после обновления),
получало `0`/`false`. Для `maxActiveTrials` это означало «0 забегов», для
`damageRules` — «правила урона выключены».

**Сделано:** явное слияние JSON с дефолтами (`merge`), проверка типов,
4 юнит-теста. Конфиг переехал в `config/lasttrial.json` с миграцией старого имени.

### 3. ✅ Арены не знали измерения

`ArenaData.Arena` хранил только позицию и владельца, а `SavedData` брался из
уровня первого вызова. Арена в Нижнем мире и такая же точка в Обычном мире
считались одной; снимок пола затирался чужим.

**Сделано:** поле `dim`, ключ снимка пола `измерение|позиция`, данные всегда
из `overworld`. Старые записи читаются как Обычный мир.

### 4. ✅ ПКМ по Реликвии обходил все проверки

`RelicBlock.use` запускал забег напрямую, минуя `GameManager.requestStart`:
без проверки целостности пола, без проверки лимита и без проверки владельца.
Любой мог стартовать чужую арену и слить её.

**Сделано:** `tryStart` с валидацией пола, лимитом и правом владельца (оператор — можно).

### 5. ✅ Подсказка арены сканировала ~100 000 блоков каждый кадр

`appendHoverText` вызывается на каждом кадре, а внутри — проверка 30×30 колонок
высотой до 96 блоков. Это заметные фризы при наведении на Реликвию.

**Сделано:** кэш результата на 500 мс по позиции.

### 6. ✅ «Пауза» по стенным часам ломала сервер

`System.currentTimeMillis()` в тике: любой лаг-спайк дольше 5 секунд считался
выходом в меню, волна сбрасывалась, мобы удалялись.

**Сделано:** определение паузы только для интегрированного сервера (одиночная игра).

### 7. ✅ Награда за «присутствие» без присутствия

`participants()` = владелец в любой точке мира + все в радиусе 96 блоков.
Награда за волну выдавалась им всем, включая AFK и случайных прохожих.

**Сделано:** отдельный `rewardTargets()` — только те, кто в радиусе арены + 24.

### 8. ✅ Магазин проверял тир по «запомненному» значению

`tierFor(player)` возвращал тир, с которым магазин открыли. Открыв витрину на
вечной Реликвии, можно было купить её товары, стоя у малой.

**Сделано:** проверка по фактическому тиру активного забега.

### 9. ✅ Утечка персональных карт

`shopTier` и `LAST_BUY` в `ShopManager` не чистились при выходе игрока —
на больших серверах карты растут бесконечно.

**Сделано:** `forget(UUID)` на `DISCONNECT`.

### 10. 🟡 Тотемы усиливают PvP вне арены

Миксин `hurt` применяет бонус тотемов к любому урону игрока по любому существу,
включая PvP в другом конце мира. Это меняет баланс чужих режимов.

**План:** флаг `pvpRules` (по умолчанию off) или применение только к мобам
с меткой `festival_mob` и к цели внутри арены.

### 11. ⏳ Дорогой скан границ

`enforceArenaBounds` обходит AABB радиусом 200 каждые 2 секунды на каждый забег.

**План:** держать список UUID мобов (он уже есть) и проверять только их,
AABB кэшировать в поле забега.

### 12. ⏳ Дорогая сверка живых

`reconcileAlive` — скан 160 блоков раз в 10 секунд. При трёх забегах это
три больших обхода сущностей.

**План:** включать скан только при рассинхроне (волна висит дольше таймаута),
в обычном режиме доверять множеству UUID.

### 13. ✅ Мобы копают любые блоки

`RelicAttackGoal` ломает блок на пути к алтарю без ограничения по материалу.
На сервере это разрушает чужие постройки вокруг арены.

**Сделано:** копание только внутри зоны арены (радиус +1, высота 0…+4), блоки
прочностью до 10, чёрный список неразрушимых. Флаг `mobDigging`.

### 14. ✅ Арена не защищена от чужих рук

Во время забега посторонний может ломать плитку и ставить блоки в площадку.
От взрывов защита есть (снимок пола), от игрока — нет.

**Сделано:** `ArenaGuard` + события Fabric: во время забега ломать и ставить блоки
в зоне может только владелец или оператор; Реликвия защищена отдельно.
Флаг `protectArena`. Взрывы криперов арены больше не разрушают блоки.

### 15. ⏳ Реликвия регенерирует в бою

`RelicBlockEntity` лечит 1 HP каждые 3 секунды всегда, даже между волнами
с полным запасом. Это снижает ценность починки за монеты.

**План:** регенерация только вне активной волны (или с задержкой после урона).

### 16. ⏳ Урон по алтарю и копание без потолка

`RELIC_DAMAGE_MULT = 2.0` и интервал копания 12 тиков не зависят от сложности:
на вечной Реликвии это те же числа, что на малой.

**План:** масштабировать от волны, вынести в конфиг.

### 17. ⏳ Бонус присутствия не сохраняется

Перезапуск сервера сбрасывает накопленные 5 минут. Награда не теряется,
но прогресс — да.

**План:** писать `presentTicks`/`bonus` в NBT забега.

### 18. ⏳ Нет предела числу участников

HUD и награды линейно растут с числом игроков у арены; сорок человек получат
награду за одну волну.

**План:** мягкий предел (например, 8) или деление награды на число участников.

### 19. 🟡 Остановка забега не оставляет следа

`Trial.stop()` молча убирает мобы и HUD. Для админа нет записи, кто и почему
остановил, а игроки видят только «испытание остановлено».

**План:** писать в лог причину и инициатора, отдельное сообщение в чат.

### 20. ⏳ Снимок пола живёт только в памяти

После рестарта сервера дыры от взрывов не заделываются до следующего старта
забега (снимок снимается заново уже с дырами).

**План:** хранить снимок в NBT блочной сущности.

## B. Ошибки процесса и развития

### 21. ✅ Не было истории версий

Один коммит, версия 0.1.0 при куче изменений, релиз без описания.

**Сделано:** осмысленные коммиты, теги, релизы, `CHANGELOG.md`.

### 22. ✅ Диффы шумели переводами строк

Windows-разработка без `.editorconfig` → CRLF против LF в каждом коммите.

**Сделано:** `.editorconfig` с `end_of_line = lf` для исходников.

### 23. ⏳ Тесты только на математику

22 теста покрывают экономику, тиры и конфиг. Поведение в бою (волны, ИИ,
урон) не покрыто: Fabric GameTest не подключён.

**План:** GameTest-сценарий «поставить Реликвию → старт → убить волну → награда».

### 24. ⏳ Нет статического анализа

Опечатки в ключах локализации, неиспользуемые импорты и `null`-контракты
ловятся только компилятором.

**План:** Checkstyle/SpotBugs в CI, запрет `System.out`, проверка паритета ключей.

### 25. ✅ Локализация без контроля паритета

Ключи добавлялись вручную в два файла, рассинхрон не проверялся.

**Сделано:** паритет ru/en сверен (0 расхождений). **План:** тест на паритет.

### 26. ✅ README обещал больше, чем есть

Разделы про TACZ, отладочный жезл и порт 26.2 описывали несуществующее.

**Сделано:** README переписан по факту.

### 27. ⏳ Нет контрибьют-документации

Нет `CONTRIBUTING.md`, шаблонов issue/PR: стороннему разработчику неясно,
как собрать и что считается приемлемым изменением.

**План:** CONTRIBUTING + шаблон баг-репорта с версией и логом.

### 28. ⏳ Нет метаданных для площадок

Modrinth/CurseForge требуют описание, категории, иконку, галерею и лицензию
в конкретном формате.

**План:** подготовить `modrinth.json`-описание и 3–5 скриншотов.

### 29. ⏳ Нет фиксации зависимостей

Версии Fabric API и Loom берутся из `gradle.properties`, но транзитивные
зависимости не залочены — сборка может отличаться через месяц.

**План:** dependency locking Gradle + проверка в CI.

### 30. ⏳ Документация только на русском

Для международной аудитории нужен английский README (или двуязычный).

**План:** `README.en.md` и ссылка из основного.
